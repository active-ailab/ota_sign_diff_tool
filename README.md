# OTA Sign Diff Tool

## 项目简介

OTA Sign Diff Tool 仓库当前是一个尚未落地实现的项目占位仓。审批清单中的目标是根据两个不同版本的 NAS 链接或本地文件生成 OTA 差分包，并通过飞书消息通知结果；但当前 `main` 分支没有生成差分包、签名、文件选择或消息发送的业务代码。

## 核心功能

当前仓库实际具备的能力只有：

- 在向 `main` 或 `master` 推送时触发 GitHub Actions。
- 复用 `active-ailab/skills-manifest` 中的 `reusable-feishu-notify.yml@main`，将仓库名、仓库 URL、操作者、分支、事件名和提交信息传给通知工作流。
- 支持在 GitHub Actions 页面通过 `workflow_dispatch` 手动触发同一通知任务。

> 计划中的 NAS/本地文件输入、两个 OTA 版本比较、差分包生成、签名校验和任务结果通知均未在当前代码中实现，不能作为现有功能使用。

## 适用场景

当前仅适合作为：

- OTA 差分工具后续开发的空仓库和需求边界记录。
- 验证仓库 push 事件能否调用组织级飞书通知工作流。

当前不适合用于生产 OTA 包生成、签名或发布流程。

## 目录结构

```text
.
└── .github/
    └── workflows/
        └── feishu-notify.yml   # push/手动触发的可复用飞书通知工作流
```

除 Git 元数据外，当前提交树没有 README、源代码、依赖清单、配置样例、测试或可执行入口。

## 使用方法

当前没有可运行的 OTA 差分命令，也没有本地安装或启动步骤。

仓库现有工作流由以下事件触发：

- 向 `main` 或 `master` 分支 push。
- 在 GitHub Actions 页面手动执行 `Feishu Notify` 工作流。

要使通知 job 成功，仓库需要配置工作流引用的 GitHub Actions secrets：

- `FEISHU_APP_ID`
- `FEISHU_APP_SECRET`

具体通知行为由外部可复用工作流 `active-ailab/skills-manifest/.github/workflows/reusable-feishu-notify.yml@main` 决定，不在本仓库内实现。

## 后续实现建议

在开放实际使用前，至少应补齐并评审以下内容：

1. 明确支持的 OTA 输入格式、NAS 下载方式和本地文件参数。
2. 实现版本校验、差分包生成、签名/验签及产物完整性检查。
3. 将凭据放入安全的 Secret 管理系统，不在命令行、日志或仓库中暴露。
4. 增加失败回滚、临时文件清理、超时、重试和产物留存策略。
5. 提供可复现的命令行入口、依赖锁定、样例配置和自动化测试。
6. 区分“仓库变更通知”与“OTA 任务结果通知”，避免把现有工作流误认为业务通知。

## 注意事项

- 当前仓库不能生成 OTA 差分包，README 中不应给出任何未经实现验证的 OTA 命令。
- OTA 与签名产物属于高风险发布资产；正式实现需校验输入来源、版本匹配、签名密钥权限和产物哈希。
- NAS 凭据、飞书应用密钥和签名私钥不得提交到仓库。
- 外部可复用工作流使用 `@main` 引用，行为会随上游主分支变化；生产使用时应评估固定到受控版本或提交。
- 业务实现完成后，应以真实入口、参数帮助和测试结果替换本占位说明。
